Informe Técnico: OpenStreetMap (OSM) y Georreferenciación

Ejercicio 3f - Ingeniería del Software II (TP2)

¿Qué es OpenStreetMap (OSM)?

OpenStreetMap (OSM) es un proyecto colaborativo de código abierto fundado en 2004 por Steve Coast, orientado a construir un mapa mundial editable, abierto y libre. A diferencia de las plataformas privativas, los datos geográficos de OSM están disponibles bajo la licencia Open Database License (ODbL), permitiendo a cualquier desarrollador, empresa o institución consultar, descargar y procesar información espacial sin costo de licencias por consulta.

Estructura y Modelo de Datos de OpenStreetMap

El núcleo de OpenStreetMap se fundamenta en tres primitivas espaciales esenciales:

  • Nodos (Nodes): Puntos en la superficie terrestre definidos por su latitud y longitud (WGS 84). Se utilizan para modelar puntos de interés (POIs), paradas, o la ubicación de un proveedor como en nuestro sistema.
  • Vías (Ways): Secuencias ordenadas de nodos (entre 2 y 2.000) que representan elementos lineales (calles, avenidas, ríos) o polígonos cerrados (edificios, parcelas, lagos).
  • Relaciones (Relations): Colecciones de nodos, vías u otras relaciones con roles asignados, utilizadas para representar estructuras complejas como rutas de transporte público o fronteras provinciales.
Arquitectura de Teselas (Tile Server) y Leaflet.js

Para renderizar mapas rápidamente en navegadores web sin descargar gigabytes de geometría vectorial, los servidores de OSM pregeneran imágenes rasterizadas o teselas vectoriales de 256x256 píxeles organizadas en pirámides de niveles de zoom:

https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png
Donde z es el nivel de zoom, y x / y son las coordenadas de la tesela en la proyección Mercator esférica (EPSG:3857).

Leaflet.js es la librería ligera cliente en JavaScript de referencia recomendada por la cátedra para renderizar estas teselas de OpenStreetMap de forma fluida, manejar zoom, arrastre (pan), interactividad, popups y capas de marcadores sin sobrecargar la memoria del cliente.

Implementación en el Sistema E-Commerce
  1. Modelo de Dominio (Supplier): Se modeló la entidad Proveedor con atributos de localización: address, latitude (double) y longitude (double).
  2. API RESTful (SupplierController): Expone endpoints para consultar la lista de proveedores geolocalizados (GET /api/suppliers) y registrar nuevos (POST /api/suppliers).
  3. Integración Frontend: Leaflet.js consume los datos de los proveedores y genera marcadores geolocalizados en el mapa interactivo con OpenStreetMap.
